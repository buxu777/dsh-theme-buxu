# dsh-theme-buxu · 不虚 · 质肤

DeepSeek Harness 的主题与界面个性化插件。它不是独立网页，而是通过 DSH 插件运行时提供配色方案、对话头像、推理等级滑块配色，以及若干会话增强功能。

**设计取向**：不加装饰的主题，只补你每天要用的功能。不叠壁纸、不改布局结构、不做毛玻璃 —— 所有配色通过 DSH 官方 `--dsw-alias-*` token 注入，界面结构与官方完全一致。

## 功能

### 六套配色方案

| 配色 | 基调 | 强调色 | 推理条 |
|---|---|---|---|
| 质肤 · 石墨 | 深色 · 中性 | `#A5ADB6` 灰 | 石墨灰 |
| 质肤 · 墨玉 | 深色 · 墨绿 | `#62BC8F` 青绿 | 青蓝绿 |
| 质肤 · 藏青 | 深色 · 靛蓝 | `#5D8AC6` 蓝 | 单色蓝阶 |
| 质肤 · 石墨紫 | 深色 · 紫灰 | `#9681CF` 紫 | 靛紫粉 |
| 质肤 · 云白 | 浅色 · 中性 | `#465F72` 蓝灰 | 石墨灰 |
| 质肤 · 宣纸 | 浅色 · 暖米 | `#8D5E35` 棕褐 | 暖阳 |

- **配色自带强调色与推理条**：切换配色时，强调色和推理强度条一起切换，不会「只变了底色」。
- **可覆盖、可恢复**：手动改过强调色或推理条后，切换配色不再覆盖你的选择；设置页有「恢复跟随配色」入口。
- **明度阶梯**：每套配色的内容区 / 侧栏 / 卡片 / 浮层 / 输入框各自差一档，边界看得清又不抢戏。

### 对话头像

- 默认用户头像为「我」字方块，**六套配色各一版**，随配色自动切换（保留原图深底白字的设计，白字对比全部 ≥ 4.5:1）。
- 助手头像沿用内置图。
- 支持上传 PNG / JPEG / WebP（上限 8 MB、1600 万像素），裁剪压缩为 128×128 PNG 后保存。
- 保存最近使用过的 3 张自定义头像，可点击直接切换；上传过自定义图后以自己的图为准。
- 「恢复默认」回落到当前配色的内置头像。

### 推理强度条

- 6 套内置渐变（单色蓝阶 / 暖阳 / 青蓝绿 / 靛紫粉 / 石墨灰 / 珊瑚朱）+ 自定义 4 色取色器。
- 可另存为命名预设，最多 6 个。
- 独立的气泡粒子开关，任意配色都能叠加。

### 会话增强

- **回退对话**：每条用户消息旁的 `↶` 回退到那一轮之前，原文本自动放回输入框，可直接改写后重发。走官方 surface replacement，不改写会话日志。
- **会话标记**：侧栏会话右键可标「显示待办」`○` / 「重要」`◆`，与官方圆点同尺寸对齐，重启后保留。标记色按配色深浅自适应（深色用亮档、浅色用暗档）。
- **复制到工作区**：在目标工作区新建空白会话，标题派生自原标题。原会话不受影响。
- **刷新 / 重启**：会话头部按钮。刷新只重载渲染层；重启会关闭并重新启动 DSH（需重新加载 Host 半时用）。

### 兼容性

- 配色全部通过官方 `--dsw-alias-*` token 覆盖实现，不改写官方布局。
- 关键 DOM 契约探针保留，升级后可在高级设置查看状态。
- 选中文字、附件删除键、发送按钮等都用 `color-mix` + 主题 token 自适应，新增配色无需逐项调整。

## 安装

从插件市场安装（推荐）：

在 DSH 的 插件 → 发现 里搜索 `dsh-theme-buxu`。

或用命令行：

```sh
dsh plugin --profile desktop add dsh-theme-buxu
```

从本地工作区安装：

```sh
dsh plugin --profile desktop add E:/DSH/dsh-theme-buxu
```

卸载：

```sh
dsh plugin --profile desktop remove dsh-theme-buxu
```

修改客户端代码后可在现有窗口按 F5 重新加载；修改插件注入声明、包元数据或 Host 入口后，需要按 DSH 流程重启。

## 关于「重启应用」（请先读这一段）

插件包含一个关闭并重新启动 DSH 的功能。它**会终止当前 DSH 进程**，所以这里明确说明它做什么、不做什么：

**做什么**

- 仅在你**主动点击**「重启应用」并**在二次确认里点「确认重启」**之后才执行。
- 只终止 DSH 自身的进程，**按 PID 精确匹配**，不使用进程树终止（不会连带杀掉你的终端、编辑器或其它程序）。
- 关闭后由一个小型 Node 脚本等待旧进程退出，再重新拉起 DSH。
- 过程日志写到系统临时目录（可用 `BUXU_LOG` 覆盖）。

**不做什么**

- **不自动执行**，没有任何定时器、启动钩子或后台任务会触发它。
- **不联网**，不上传任何数据。插件整体没有任何网络请求。
- **不修改你的配置文件**，不改 `cordis.patch.yml`，不动会话数据。
- 不支持跨机器操作，只作用于本机当前进程。

**为什么需要它**：DSH 分为「渲染层」和「Host 半」两部分。改配色这类只涉及渲染层的改动，按 F5 刷新即可；但改动了 Host 半（例如插件配置结构）时，必须让 Host 重新加载，只能重启。没有这个按钮时，你得手动退出再双击启动器。

如果你不需要这个功能，忽略它即可 —— 它不会自己运行。

## 冷重启的可选环境变量

「冷重启」默认自动推导 DSH 可执行文件与日志位置，通常无需配置。特殊安装方式下可用：

| 变量 | 作用 | 默认 |
|---|---|---|
| `BUXU_DSH_EXE` | 指定新实例要启动的 DSH 可执行文件 | 从当前进程推导（`DeepSeek Harness.exe`） |
| `BUXU_CLEANER` | 可选：启动前执行的认证 cookie 清理脚本（`.ps1`） | 未设置则跳过清理 |
| `BUXU_LOG` | 重启过程日志路径 | 系统临时目录 `dsh-theme-buxu-restart.log` |

**解析不到 `BUXU_DSH_EXE` 时，真实重启会被明确拒绝**（避免「关掉却起不来」）。点「重启应用」时插件会先做一次前置检查，检查不通过会直接显示原因，不会让你先点「演练」才知道。

> 为什么需要清理 cookie：桌面版 DSH 每次启动监听新的随机端口，认证 cookie 名随端口变化、30 天才过期。累积约 70 条后 welcome 认证会失败。该清理脚本属于用户自备，插件不附带。

## 配置与持久化

Host 配置入口为 `ui-theme-buxu`，与 `cordis.patch.yml` 一致；npm 包名为 `dsh-theme-buxu`，两者不能混用。

客户端通过 `ctx.configForms.get('ui-theme-buxu')` 读取快照和写入。设置采用乐观预览、最新操作代次裁决、Host 接受校验和失败回读；多字段恢复默认使用单次 `mutate`。配置不可用或只读时，界面明确显示「临时预览」，不承诺重启后保留。

配色备份仅用于缺失/非法快照的恢复，不覆盖 Host 的明确合法值。自定义头像以 Host 配置为准，旧 localStorage 只作迁移/兼容回退。

## 扩展

`lib/client.js` 的 `PALETTES` 注册表管理色板；每套色板除了 22 个颜色槽位，还带 `accent`（自带强调色）和 `effort`（推荐推理条）两个字段。新增配色只需在 `PALETTES` 里加一条，并同步 `lib/index.js` 的 `PALETTE_IDS`。

几何默认值由 `GEO` 管理。`lib/index.js` 声明 Host 配置 schema，客户端和服务端的字段、默认值及 Host 入口必须保持一致。

## 设计原则

1. **平面**：纯色块，不用渐变、玻璃、背景图。
2. **单色相**：靠明度构层次，色相饱和度压到 8~15%。
3. **文字色不跟着色相走** —— 避免正文发绿/发蓝/发紫导致长文阅读疲劳；强调色单独取更饱和的值，只用于小面积点睛。
4. **功能语义色保持稳定**：待办蓝、重要橙、错误红不随主题变色（它们表达状态而非品牌），但明度按深浅分档保证可读。
